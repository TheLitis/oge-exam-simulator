## Открытие и остановка

В терминале PowerShell 7 из корня проекта:

```powershell
.\scripts\mos\Open-MosTestbed.ps1
```

Команда запускает сохранённую VM и локальную консоль, затем открывает её в браузере. Консоль также доступна по адресу [http://127.0.0.1:13600/](http://127.0.0.1:13600/). После перезапуска VM нажмите «Подключить» в консоли. Нажатие на экран или «Управлять» передаёт клавиатуру в МОС; зелёная подпись под экраном подтверждает фокус. Переключение раскладки внутри МОС — Alt+Shift.

Для совпадения кликов с экраном используется абсолютное устройство `QEMU HID Tablet`. Запуск закрепляет `-machine q35,vmport=off`: без этого эмуляция VMware `vmmouse` перехватывала ввод в относительном режиме, и клики не попадали в элементы интерфейса. Исправление применяется при следующем запуске VM и сохраняется после перезагрузки гостевой ОС.

После остановки и повторного запуска 10 октября 2026 года `query-mice` подтвердил активный USB-планшет с `absolute=true` и отсутствие `vmmouse`. Во встроенном браузере на `127.0.0.1:13600` проверены клик по демонстрационному варианту, ввод `test123` и `тест123` в форму участника, переключение раскладки через Alt+Shift, переключение масштаба и возврат клавиатуры кнопкой «Управлять». Ошибок JavaScript в консоли браузера не обнаружено. Экзамен в этом проходе не запускался.

На рабочем столе МОС расположен ярлык **«Симулятор экзамена ОГЭ»**. После графической установки приложение находится в `/home/mosqa/.local/opt/oge-exam-simulator/current`, использует собственный Node.js `22.16.0` и запускается от `mosqa`. Ярлыки в меню и на рабочем столе создаются двойным щелчком по «Установить» из распакованного архива. Терминал и sudo не нужны; исходную папку распаковки можно удалить. Прежняя копия в `/home/mosqa/Applications` сохранена для истории проверок. Пароль тестовой учётной записи сохранён только локально в `.mos-testbed/credentials.json`.

Штатное выключение с сохранением данных:

```powershell
.\scripts\mos\Stop-MosTestbed.ps1 -StopConsole
```

Скрипт сверяет PID, исполняемый файл и время запуска. Он запрашивает выключение гостевой ОС через QGA и подтверждает завершение VM. При невозможности штатного выключения он сообщает ошибку и сохраняет запущенную машину.

Штатный перезапуск установленного стенда с сохранением диска, памяти, числа ядер и ускорителя:

```powershell
.\scripts\mos\Restart-MosTestbed.ps1
```

Команда сначала выключает MOS и подтверждает выход именно записанного процесса QEMU, затем загружает тот же диск и оставляет локальную консоль доступной. При ошибке или неподтверждённом выключении запуск прерывается, принудительное завершение не используется. После загрузки нажмите «Подключить» в консоли и откройте симулятор с ярлыка.

В полном прогоне мягкая перезагрузка гостевой ОС привела к остановке WHPX с `Unexpected VP exit code 4` уже после штатного отключения файловых систем MOS. Это совпадает с [описанием проблемы WHPX/UEFI в QEMU](https://gitlab.com/qemu-project/qemu/-/issues/2402). Для Installed+WHPX запуск теперь задаёт поддерживаемую [опцию `-action reboot=shutdown`](https://www.qemu.org/docs/master/system/qemu-manpage.html): команда перезагрузки внутри MOS выключает VM. Затем выполните `Open-MosTestbed.ps1` или `Restart-MosTestbed.ps1`. Предпочтительный путь проверки перезапуска — команда выше. Хостовые настройки гипервизора не меняются.

Обход проверен на живом стенде: `Restart-MosTestbed.ps1` вернул рабочую Plasma, отдельный запрос `guest-shutdown(mode=reboot)` завершил QEMU без ошибки WHPX, последующий запуск восстановил готовый результат. Новая опция применяется при следующем запуске VM; режимы Live/Installer и ускоритель TCG её не получают.

## Повторная установка

Для повторения нужны сохранённые артефакты `imported/chatgpt/oge-exam-simulator-linux-x64.tar.gz` и `oge-exam-source.zip`, Node.js и PowerShell 7 на Windows.

1. `Initialize-MosTestbed.ps1` скачивает и проверяет закреплённый официальный ISO, устанавливает QEMU из winget и зависимости консоли из npm по lockfile.
2. `Start-MosTestbed.ps1 -Mode Live` запускает официальный live-образ; `prepare.cjs` формирует локальный kickstart с отдельным случайным паролем тестовой VM.
3. `payload.cjs` временно выдаёт только kickstart и два сохранённых архива по loopback-порту 13601; из VM он доступен как `10.0.2.2`.
4. После штатной остановки live-режима `Start-MosTestbed.ps1 -Mode Installer` устанавливает МОС на выделенный виртуальный `/dev/vda`. Этот режим очищает только виртуальный диск стенда. По завершении установщик выключает VM.
5. `Start-MosTestbed.ps1 -Mode Installed` загружает установленный диск. `guest.cjs scripts/mos/provision-guest.sh` переносит и проверяет архивы, устанавливает ярлык и запускает проверки от `mosqa`.
6. `Collect-MosEvidence.cjs` сохраняет журналы гостевых проверок на Windows и переключает `bootMode` в `.mos-testbed/config.json` на `Installed` после подтверждения загрузки с диска и 42 успешных тестов. Временный сервер `payload.cjs` после переноса закрывается.

После штатного выключения `Save-MosSnapshot.ps1` сохраняет снимок QCOW2 и отдельную копию UEFI-переменных. Команда повторного запуска использует существующий диск и сохраняет данные предыдущей работы.

Kickstart использует штатный `/dev/mapper/live-base`, который Dracut создаёт из проверенного ISO. Это позволяет автоматической установке МОС копировать оригинальную базовую систему без повторного подключения занятого loop-устройства.

Консоль, VNC, QMP, QGA и SSH-перенаправление слушают только `127.0.0.1`. Доступ извне компьютера не включён. Виртуальная сеть использует NAT. Хостовые управляющие порты: консоль 13600, QMP 14500, QGA 14501, VNC 15900, SSH 22222.
