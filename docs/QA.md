# Проверки версии 1.0.0

Дата полного функционального прогона: **10 октября 2026**. Среда: установленная **МОС Desktop 12, MOS-V 260926**, Linux x86_64, Plasma 5.27.11, Chromium 151.0.7922.137, экран гостевой ОС 1280×800. Используется Node.js 22.16.0 из переносимой поставки. Состав виртуальной машины описан в [MOS-TESTBED.md](MOS-TESTBED.md).

Интерфейс проверен в обычном окне приложения Chromium внутри MOS, через живую консоль VM. Загружены штатные HTML, ES-модули, изображения и loopback API с авторизацией и CSP. Все ответы введены через интерфейс, файлы выбраны в системном диалоге MOS. Снимки состояния и файлы затем прочитаны независимо для сверки.

## Автоматические проверки

На MOS и Windows успешно выполнены `npm run check` и `npm test`: **12 JavaScript-файлов, 45 тестов без ошибок и пропусков** (36 проверок модели/файлового сервиса, 9 HTTP-проверок).

Покрытие включает 16 заданий, регистрацию с ведущими нулями, активацию, снимки файлов, отдельные черновики, сохранение и удаление ответа, восстановление, отказ в поздней записи, автоматическое и идемпотентное завершение, экспорт, повторный экспорт после ошибки записи, проверки импорта и защиты loopback API. Добавлены регрессии для старой блокировки с повторно использованным PID, неопределённого ответа health и восстановления конфигурации перед завершением.

Проверки срока выполняются с внедрёнными тестовыми часами. Таймер пользовательского экзамена остаётся равным **9 000 000 мс (150 минут)**. Полный непрерывный 150-минутный прогон ещё не выполнялся.

## Исправленные ошибки

1. Проверки одного PID было недостаточно после аварии или перезагрузки: старый PID мог принадлежать другому процессу. Перед повторным открытием проверяется авторизованный health сервиса; при неопределённом ответе второй таймер не запускается.
2. Найденный при утрате конфигурации сеанс не записывал свой ID обратно. После завершения и следующего запуска результат мог исчезнуть с экрана. Восстановление теперь сохраняет ID в конфигурации; полный путь проверен на MOS.
3. Поле кода активации вызывало предложение Chromium сохранить пароль с паспортным номером как логином. Код теперь вводится в обычное текстовое поле без автозаполнения; повторная активация проверена в отдельной папке данных.
4. WHPX зависал на мягкой перезагрузке UEFI с `Unexpected VP exit code 4` после штатного отключения файловых систем MOS. Добавлена команда штатного выключения и холодного запуска; Installed+WHPX использует поддерживаемый `reboot=shutdown`. Проверены оба пути, включая запрос перезагрузки из гостевой ОС и последующий запуск. Это обход ограничения виртуализации; команда описана в [MOS-TESTBED.md](MOS-TESTBED.md).
