# Проверки версии 1.0.0

Дата: 9 октября 2026. Среда: Debian 13 Linux x86_64, Node.js 22.16.0. Готовая сборка не испытывалась на физическом школьном компьютере с MOS ОС.

## Автоматические тесты

Команды: `npm run check`, `npm test`. 12 JavaScript-файлов прошли синтаксическую проверку. **42 теста**: 35 проверок модели/файлового сервиса и 7 HTTP-проверок.

Покрытие: 16 заданий и матрица типов; ровно 9000 секунд; обязательная регистрация и ведущие нули; соль и scrypt; отсутствие старта без кода; ограничение редактора при активном экзамене; разделение черновика и сохранённого ответа; снимок прикреплённого файла; замена и удаление ответа; восстановление после перезапуска; истечение срока на перезапуске; защита времени от отката часов в работающем процессе; отказ в поздней записи; автоматическое завершение даже без опроса браузера; идемпотентное завершение; все 16 записей, паспортные поля, файлы и контрольные суммы в ZIP; ошибки записи и повторный экспорт.

Импорт/защита: строгая лексикографическая сортировка; валидация изображения и публикации; круговой экспорт/импорт; несовпадение SHA-256; ZIP traversal; симлинки; дубликаты; поддельный размер; флаг шифрования; ограниченный поток записи; экранирование HTML/CSV; обязательный токен; Origin/Host/Sec-Fetch-Site; отсутствие произвольного чтения файлов; подтверждение завершения; единственный экземпляр процесса.

**Проверки времени ускоренные:** часы внедряются в тестовый экземпляр сервиса, а не меняются в пользовательском интерфейсе. Непрерывный реальный прогон в течение 2,5 часов не выполнялся.

## Проверка графического интерфейса

Browser plugin в сессии не был доступен. Использован Playwright с системным Chromium. Прямая навигация этого Chromium на локальный URL была заблокирована политикой среды (`ERR_BLOCKED_BY_ADMINISTRATOR`). Политика не отключалась и не изменялась.

Поэтому UI проверялся **на изолированной about:blank-странице**: тот же HTML/CSS/JavaScript, встроенные локальные статические ресурсы и явный тестовый транспорт к реальному loopback API. URL/сессионный токен для тестовой страницы внедрялись стендом. Это проверка отображения, логики интерфейса и её взаимодействия с реальным сервисом, **но не полный нативный запуск с обычной загрузкой ES-модулей, browser-origin и CSP**. HTTP-заголовки и авторизация проверялись отдельно. Эти границы нельзя выдавать за проверку целевого MOS-браузера.

Проверенный пользовательский путь: главная -> демо -> регистрация -> активация -> ввод и сохранение ответа -> прямой переход -> два изображения условия -> скачивание исходного материала -> системный выбор файла -> сохранение файла -> окно завершения -> отмена -> повторное завершение -> скачивание итогового ZIP и проверка его содержимого. Отдельно: редактор -> массовый импорт изображений -> добавление материалов 11–14 -> генерация кода -> экспорт готового .oge. Отдельный запуск подтвердил переход к результату и закрытие диалога при истечении времени.

Разрешения: 1366×768, 1366×900, 1440×1000 и узкое 390×844. Проверены читаемость текста, расположение таймера и номера задания, видимость кнопки сохранения, вертикальное размещение изображений, состояния выбора/сохранения, модальные кнопки и отсутствие горизонтального переполнения на узком экране. Ошибок JavaScript в выполненных изолированных сценариях не зафиксировано.

Найдено и исправлено: CSS переопределял скрытие служебных file-input; сетка навигации выходила за ширину 390 px; ошибка создания каталога результатов могла не попасть в обработчик повторного экспорта. Скриншоты QA сделаны с вымышленными регистрационными данными и находятся отдельно от репозитория.

## Что ещё проверить при приёмке

Реальный MOS-образ и его браузер, открытие через меню/файловый менеджер, политики локальных адресов и скачивания, запуск внешнего офисного ПО, аварийное отключение питания и реальный 150-минутный прогон. Используйте `MOS-CHECKLIST.md`. Совместимость с ними не заявляется подтверждённой только на основании тестов Debian.

## Проверка переносимой поставки

Архив .tar.gz распакован в новый временный каталог. `start.sh` запущен с PATH, в котором есть только `dirname` и `uname`, но нет команд `node` и `python`: используется исключительно вложенный `runtime/node`. Через API распакованной сборки проверены health, загрузка встроенного демо, активация, сохранение, завершение, итоговый ZIP и штатное закрытие процесса. Все шаги прошли. Это проверка зависимости от runtime, не утверждение об удалении Python из тестовой ОС.

`install-menu.sh` также проверен с отдельным временным XDG_DATA_HOME: создан корректный .desktop-файл текущего пользователя, без административных изменений. Реальное отображение этого ярлыка в меню MOS требует проверки на целевой машине.
