# Симулятор экзамена — ОГЭ по информатике

Локальное учебное приложение: **16 заданий, 150 минут, редактор вариантов, необязательная автопроверка для учителя и зашифрованные результаты**. Проект TheLitis. Версия 1.6.0.

Готовая Linux-сборка содержит собственный Node.js: для экзамена и редактора устанавливать **Python, Node.js, npm или сервер не требуется**. Необязательная проверка программ использует системные bubblewrap/prlimit и Python 3, если выбран этот язык. На стенде MOS они уже есть. Графический интерфейс открывается в установленном браузере. Сервис слушает только `127.0.0.1`; интернет и внешние сервисы приложению не нужны.

**Статус платформы:** целевая система — MOS ОС, Linux x86_64. На установленной виртуальной МОС Desktop 12 (MOS-V 260926) с Chromium 151 ранее пройден функциональный экзамен из 16 заданий, проверены восстановление, ZIP результата и автопроверка настоящих файлов Calc/Impress. Для версии 1.6.0 в MOS проходят 211 автоматических тестов с обязательной песочницей, 1 проверка неподдерживаемой платформы пропущена; на Windows — 198 тестов и 4 ожидаемых пропуска. Отдельный полный прогон через локальный API в MOS дал 16 из 16 правильных ответов: проверены реальные перезапуски ученического процесса, восстановление зашифрованной работы без ключа, целостность ZIP и перенос ключа на другую установку. Новые проверки используют обычные производственные настройки: зашифрованные итоги, активное/завершённое восстановление, перенос ключей, повреждённые работы и шифрование прежних копий. Интерфейс ранее проверен в отдельной Windows-среде со служебными данными: светлая/ночная тема, узкий экран, импорт эталона и многострочный ввод; новые элементы проверены сценариями интерфейса. Физический школьный компьютер и непрерывный 150-минутный сеанс ещё требуют проверки по `docs/MOS-CHECKLIST.md`.

Исходники и полная история изменений: [TheLitis/oge-exam-simulator](https://github.com/TheLitis/oge-exam-simulator). Готовый установщик для MOS, архив исходников с историей Git и контрольные суммы находятся в [Releases](https://github.com/TheLitis/oge-exam-simulator/releases).

## Запуск готовой программы

Откройте `oge-exam-simulator-linux-x64.tar.gz` в Ark и распакуйте весь архив. В папке дважды щёлкните **«Установить»**. Если MOS спросит, что сделать с файлом, выберите **«Выполнить»**, затем подтвердите установку в графическом окне. По завершении нажмите **«Запустить»**.

В меню приложений и на рабочем столе появится **«Симулятор экзамена ОГЭ»**. Для повторного запуска дважды щёлкните ярлык. **Терминал, sudo и пароль администратора не нужны.** Приложение устанавливается только текущему пользователю в `~/.local/opt/oge-exam-simulator/`; распакованную папку после установки можно удалить. Для обновления повторите установку из нового архива. Экзамены и результаты хранятся отдельно и сохраняются при обновлении.

Для пробы без установки дважды щёлкните **«Запустить»** в распакованной папке. Внутри также находится `НАЧАТЬ-ЗДЕСЬ.txt`. Графический установщик использует KDialog, входящий в проверенную МОС Desktop 12 с Plasma.

Приложение запускает локальный сервис и открывает интерфейс. В Chromium / Яндекс Браузере используется отдельное окно приложения, в остальных случаях — стандартный браузер через `xdg-open`. Браузер в поставку не входит. Подойдёт современный Chromium / Яндекс Браузер / Firefox с поддержкой JavaScript, Blob, `<dialog>` и выбора файлов.

Для запуска из терминала при разработке остаётся `./start.sh`. Для установки из скриптов `./install-menu.sh` выполняет ту же установку текущему пользователю. Не запускайте программу от root.

В версии 1.6.0 поставляется Node.js **22.23.3** из официального дистрибутива; архив сверяется с опубликованной SHA-256. Runtime фиксирован, для его обновления нужна повторная сборка. Требования бинарного файла: `GLIBC_2.28`, `GLIBCXX_3.4.21`, Linux x86_64.

## Быстрая проба

Кнопка с луной в верхней панели включает ночную тему; кнопка с солнцем возвращает светлую. Выбор сохраняется на этом компьютере после закрытия приложения и перезапуска. Переключение доступно во время экзамена, введённые ответы остаются на месте.

Нажмите **«Открыть демонстрационный экзамен»**. Для первой пробы задайте пароль учителя: он позволит открыть зашифрованный результат. Затем заполните регистрацию вымышленными данными и введите код **`DEMO-2026`**. В демо есть все 16 условий, два изображения для задания 3 и исходные файлы для заданий 11–14.

Демонстрационные задания созданы для проверки приложения; они не являются официальным вариантом ФИПИ. Учитель может задать эталоны и критерии автопроверки. Автоматического выставления официальных баллов нет.

## Как проходит экзамен

Регистрация требует номер бланка, фамилию, имя, серию паспорта из 4 цифр и номер из 6 цифр. Ведущие нули не теряются. Выполняется проверка заполнения и формата, **не проверка личности по государственным базам**. Без правильного кода активации запуск невозможен.

| Задания | Ответ | Исходные файлы для скачивания |
|---|---|---|
| 1–10 | Краткий текстовый ответ | Нет |
| 11–12 | Краткий текстовый ответ | Да |
| 13–14 | Файл | Да |
| 15–16 | Файл | Необязательно |

Слева расположены все 16 номеров. Работают прямой переход, «Предыдущее» и «Следующее». Статусы различают сохранённый ответ, черновик и отсутствие ответа.

**«Сохранить ответ» — обязательное действие для сдачи ответа.** Сочетание Ctrl+Enter делает то же самое. Текстовые черновики дополнительно записываются во время ввода. Выбранный файл немедленно копируется в сеанс, но становится сданным ответом только после нажатия кнопки сохранения. При изменении исходного файла в редакторе его необходимо прикрепить и сохранить заново: приложение не следит за внешним файлом автоматически.

Таймер запускается после успешной регистрации, активации и создания снимка варианта. На экзамен даётся ровно **9000 секунд**. По истечении срока сервер прекращает приём ответов и формирует результаты; всплывающее окно подтверждения не останавливает таймер. Ручное завершение требует отдельного подтверждения и показывает число сохранённых ответов и черновиков.

Закрытие вкладки не останавливает локальный процесс и не ставит таймер на паузу. Повторный запуск ярлыка открывает тот же процесс. Завершить само приложение можно кнопкой питания в шапке. При следующем запуске сохраняются ответы и первоначальный срок экзамена. Если компьютер или процесс не работал в момент истечения срока, итог формируется **при следующем запуске**, а не физически во время выключенного компьютера.

## Создание экзамена

Откройте **«Редактор экзамена»**. При первом входе задайте пароль учителя от 10 до 128 символов **до передачи компьютера ученику**. Этот пароль закрывает редактор и проверку работ, шифрует локальный проект и его эталоны. Сохраните пароль отдельно: восстановление не предусмотрено. Возврат на главную, кнопка с замком и начало экзамена закрывают режим учителя; после перезапуска нужен повторный вход. Сеанс учителя действует 15 минут.

Введите название и задайте код активации: собственный из 6–128 символов либо сгенерированный приложением. Пароль учителя и код активации экзамена — разные значения. Сохраните код отдельно: в проект записываются соль и scrypt-хеш, не исходный код. После перезапуска редактор позволяет заменить забытый код новым.

Подготовьте изображения по схеме:

```text
1.1.png
1.2.png
2.1.jpg
...
16.1.png
```

Нажмите **«Импорт изображений из папки»** или **«Выбрать изображения»**. Программа распределяет файлы по заданиям. Неподходящие имена пропускаются с уведомлением. Поддерживаются PNG, JPEG, GIF, WebP и BMP; SVG не принимается. Допускаются имена с ведущим нулём, например `01.1.png`.

**Сортировка строго лексикографическая, не числовая.** Для одного задания порядок `1.1.png`, `1.10.png`, `1.2.png` именно такой. Для привычного числового порядка используйте одинаковую длину номера изображения: `1.01.png`, `1.02.png`, `1.10.png`. Изображения показываются одно под другим. Повторное добавление файла с тем же именем в то же задание заменяет его копию в проекте.

Изображения можно добавлять вручную в выбранное задание и удалять из проекта. Исходные материалы для 11–16 добавляются отдельно кнопкой **«Добавить файлы»** в соответствующем задании. Для 11–14 они обязательны; для 15–16 — необязательны. Их формат не ограничен: например, TXT, ZIP, ODT, ODS, CSV, изображения. Файл с кодом эталона открывайте в панели автопроверки, а не добавляйте в исходные материалы: исходные материалы передаются ученику.

**«Сохранить проект»** создаёт переносимый `.oge` под паролем учителя; он может быть незавершённым. Такой проект нельзя начать как экзамен. Для открытия на другом компьютере потребуется пароль, заданный при сохранении проекта. Старые незашифрованные проекты по-прежнему можно импортировать в режиме учителя; внешние старые копии не изменяются, их нельзя оставлять доступными ученикам.

**«Экспортировать экзамен»** проверяет наличие изображения в каждом из 16 заданий, материалов в 11–14 и кода активации. Только после этого создаётся готовый `.oge` для ученика без эталонов. Оба типа файлов можно повторно открыть в редакторе. Текущий рабочий проект автоматически сохраняется на компьютере.

Лимиты: до 16 изображений и 16 исходных файлов на задание; изображение до 16 МиБ; отдельный исходный файл или ответ до 128 МиБ; пакет `.oge` до 256 МиБ, распакованный — до 512 МиБ, не более 400 записей ZIP. Оставьте запас диска: при импорте и сохранении создаются отдельные копии.

## Где находятся результаты

Результаты сохраняются в обычной папке **Документы → Симулятор экзамена → Результаты**. В MOS учитывается системное расположение «Документов», включая русское имя папки. Кнопка **«Результаты»** открывает общую папку без входа учителя; **«Открыть папку»** после экзамена открывает конкретную работу. Защиту обеспечивает шифрование файлов, а не пароль на кнопку.

```text
Документы/Симулятор экзамена/Результаты/
  OGE_<дата>_<uuid>/
    result.ogeresult
```

Файл `.ogeresult` содержит ZIP работы в зашифрованном контейнере. Его можно передать учителю, но обычный архиватор не покажет ответы и регистрационные данные. Для формирования результата под учётной записью `student` не нужны sudo, учительский пароль или секретный ключ: в опубликованном экзамене находится только открытый ключ получателя.

После обновления с 1.5 и более ранних версий **один раз войдите как учитель с существующим паролем**. Приложение создаст ключ результатов и защитит свои прежние итоговые ZIP, соответствующие распакованные папки, завершённые сеансы и импортированные работы, включая прежнюю скрытую папку `results`. Сначала проверяется сохранённая зашифрованная копия, затем удаляются соответствующие открытые копии. Исходные ZIP сохраняются внутри контейнеров без изменения; при недоступных или повреждённых файлах оригинал остаётся и выводится сообщение. Внешние копии, ранее скачанные через браузер или перенесённые пользователем, не изменяются. До этого входа старые данные ещё не защищены новым шифрованием.

Рабочие данные приложения остаются отдельно:

```text
~/.local/share/oge-exam-simulator/
  editor/                 текущий рабочий проект
  exams/                  импортированные варианты
  sessions/<uuid>/        активный сеанс; после завершения — шифрованная копия и квитанция
  reviews/<uuid>/         зашифрованная копия выбранной для проверки работы
  teacher/                защищённый проект и зашифрованная связка ключей
```

При установленной переменной `XDG_DATA_HOME` рабочие данные сохраняются в ней. Для отдельного стенда `./start.sh --data /путь/к/данным` сохраняет результаты в подпапке `results` указанного каталога. Расположение результатов можно задать отдельно: `--results-dir /путь/к/результатам`. Обычный запуск с ярлыка использует «Документы». На одном компьютере не запускайте две копии с разными папками данных для одного и того же экзамена: это будут независимые сеансы.

После расшифрования учителем ZIP содержит:

```text
candidate.json           регистрация, ФИО, серия и номер паспорта
answers.json             все 16 заданий, ответы, статусы, время сохранения
answers.csv              краткая сводка
report.html              читаемый отчёт, открывается без интернета
files/task-13/...        сохранённые файлы ответов 13–16
                         (папки создаются для действительно сданных файлов)
drafts.json              несданные текстовые черновики
draft-files/task-N/...  несохранённые версии файлов, если они есть
events.json              журнал сохранений и завершения
grading-context.json     состав условий для сопоставления с проектом учителя
SHA256.json              контрольные суммы файлов результата
README.txt               пояснения к результату
```

Черновики отделены от сданных ответов и не увеличивают счётчик выполненных заданий. Кнопка скачивания сохраняет дополнительную зашифрованную копию через браузер. После завершения открытые `session.json`, `.bak` и вложения приложения удаляются только после надёжной записи защищённого архива и квитанции без регистрационных полей и ответов. Если файл в Документах удалён, приложение восстановит его из этой копии после перезапуска без ключа учителя. При конфликте существующий файл сохраняется, а работа появляется в отдельной папке. Сбой записи оставляет возможность повторного экспорта.

**Незавершённый сеанс остаётся доступным текущей учётной записи ОС для восстановления.** Ученик может читать и менять свою текущую работу. Шифрование итогов не доказывает авторство и не защищает приложение от подмены владельцем учётной записи. Удаление открытых файлов не стирает ранее сделанные копии, снимки диска или резервные копии ОС. Для тренировки используйте вымышленные данные.

В редакторе откройте **«Ключ результатов» → «Сохранить ключ»** и сохраните `.ogekeys` отдельно у учителя. Он зашифрован тем же паролем, что и учительское хранилище. На другом компьютере или под учётной записью учителя нажмите **«Импортировать ключ»** и введите пароль исходной резервной копии. Импорт добавляет старые ключи и сохраняет текущий ключ; новые работы могут использовать новый открытый ключ. Сохранение проекта `.oge` не заменяет резервную копию ключей. Утрата ключа или пароля не позволяет расшифровать результат.

## Необязательная автопроверка

В редакторе откройте «Автопроверка» у нужного задания. Для заданий 1–12 включите «Проверять ответ» и укажите один допустимый ответ на строке. Регистр учитывается по умолчанию; пробелы по краям и переносы строк нормализуются. При необходимости включите игнорирование всех пробелов.

Для заданий 13–16 можно выбрать текстовый файл, программу, электронную таблицу или презентацию. Текстовый файл сравнивается целиком в UTF-8. Для программы выберите язык решения ученика — Python 3 или JavaScript / Node.js — и задайте 1–16 запусков. **Все строки входных данных одного запуска вставляются в одно многострочное поле.** В новом запуске программа получает отдельный набор входных данных; одна строка ввода не требует отдельного запуска.

Ожидаемый вывод можно задать вручную либо включить **«Эталонная программа»**, вставить код или открыть файл `.py`, `.js`, `.cjs`. Язык эталона выбирается отдельно: эталон Python может проверять JavaScript ученика. **«Проверить эталон»** предварительно запускает его на тестах и показывает полученный вывод. В отдельных запусках можно включить ручной ожидаемый вывод, включая намеренно пустой. **«Эталон для всех тестов»** переключает все запуски на вывод программы. Эталон должен давать воспроизводимый результат на одном и том же вводе; его ошибка или недоступность среды не засчитывается ученику как неверный ответ.

Если решение читает файл, добавьте его в **«Исходные файлы»** задания. Обе программы получают одинаковые проверенные файлы под исходными именами в своих отдельных рабочих папках. Для чтения только из файла поле ввода можно оставить пустым. Эталонный код хранится только в защищённом проекте и не передаётся в рабочую папку ученика. Во время просмотра и в скачанном учительском отчёте доступны вход, ожидаемый и полученный вывод каждого теста. Проверяется весь вывод, а не наличие нужного числа среди других строк. Вариант «Точное совпадение» сохраняет пробелы и конечный перенос строки; CRLF и LF считаются одинаковыми.

Для **таблиц ODS / XLSX** добавьте от 1 до 32 критериев: значение или формулу отдельной ячейки, точное число листов, наличие листа по имени, минимальное число диаграмм на листе. Имена листов должны совпадать, адреса — например `A1` или `D12`. Текст сравнивается целиком без пробелов по краям; регистр можно отключить. Числовой критерий требует числовую ячейку и позволяет задать абсолютную погрешность; текстовая ячейка «5» не считается числом 5. Ожидаемое пустое текстовое значение проверяет пустую ячейку.

Проверяются **значения, сохранённые в файле**: формулы не пересчитываются. Перед сдачей нужно пересчитать и сохранить таблицу в Calc / Excel. Критерий формулы сравнивает её сохранённый текст; простые ссылки вида `[.A1:.A5]` в ODS и `A1:A5` в XLSX, регистр функций и разделители аргументов нормализуются. Для ввода используйте сохранённые английские имена функций, например `=SUM(A1:A5)`. Произвольная эквивалентность формул не определяется. Зависимые общие, массивные и повторённые формулы, которые требуют развёртывания, могут дать «Ошибка проверки»; отсутствующий сохранённый результат также отображается как ошибка, а не неверный ответ.

Для **презентаций ODP / PPTX** доступны точное число слайдов, текст конкретного слайда (содержит фрагмент или совпадает целиком) и минимальное число встроенных изображений на нём. Слайды нумеруются с 1 в порядке презентации, включая скрытые. Текст берётся из собственных текстовых блоков и таблиц слайда, без заметок и образцов; абзацы разделены переносом строки. Явно скрытые фигуры и группы PPTX исключены. Учитываются изображения, сохранённые отдельными частями внутри документа; внешние ссылки и редкие ODP inline `office:binary-data` не учитываются. Критерии проверяют содержимое и структуру; оформление учитель оценивает вручную.

У каждого критерия в проверке и отчёте показаны результат, ожидаемое и полученное значение. Задание считается верным, когда выполнены все заданные критерии. Если часть документа невозможно проверить, причина указана отдельно. Для ручной проверки оставьте «Ручная проверка».

Office-документ для автопроверки ограничен 32 МиБ, 256 листами/слайдами и 8 секундами чтения. Нужны обычные ODS/XLSX/ODP/PPTX без макросов и пароля; старые XLS/PPT, PDF и другие форматы можно проверить вручную. LibreOffice и Microsoft Office для самой автопроверки устанавливать не требуется. Форматирование числовых ячеек XLSX (например отображение даты) не разворачивается: сравнивается сохранённое значение.

Нажмите «Применить». Изменения также применяются при переходе, экспорте и проверке работы. **«Сохранить проект» включает эталоны, «Экспорт экзамена» исключает их.** Ученикам передавайте только экспорт экзамена; проект с эталонами оставьте у учителя. Старые проекты без эталонов продолжают работать.

Учитель открывает свой проект, нажимает «Проверить работу», выбирает `.ogeresult` ученика (или прежний `.zip`) и нажимает «Проверить». Для зашифрованной работы нужен соответствующий ключ в учительском хранилище. Проверяются только ответы и файлы из выбранного импорта; скрытые сеансы не используются как дополнительный источник. Изменение исходного файла после импорта не меняет принятую копию. У каждого задания будет результат: «Верно», «Неверно», «Нет ответа», «Ручная проверка», «Ошибка проверки» или «Проверка недоступна». Черновики не оцениваются. Если состав условий отличается или в старом ZIP нет такой информации, сначала сопоставьте вариант и явно разрешите использование текущих эталонов. Приложение не выставляет официальную оценку и не подтверждает полноту выбранных учителем тестов.

Импортированная работа, ответы, вложения и оценки хранятся в приложении зашифрованными. Расшифрованные файлы проверки временные и удаляются при завершении операции, блокировке учителя или следующем запуске после сбоя. **«Скачать отчёт» — явный экспорт открытого ZIP** с `assessment.json`, HTML, CSV и расшифрованным исходным ZIP работы; его храните только у учителя. Есть контрольные суммы. Повторная проверка заменяет отдельный учительский отчёт, не выбранный исходный файл.

Результат ограничен 256 МиБ сжатого ZIP и 512 МиБ содержимого; контейнер добавляет небольшой служебный заголовок. При превышении лимита исходный сеанс сохраняется и выводится ошибка экспорта. Прежние опубликованные варианты без ключа требуют повторного экспорта учителем либо предварительной настройки ключа на общем компьютере.

Программы запускаются только при явной проверке учителем, отдельно для каждого теста. В MOS / Linux x86_64 используются bubblewrap, prlimit, пространства имён и seccomp: без сети, домашней папки, данных приложения, записи на диск и дочерних процессов. Ограничения на тест: 4 секунды настенного времени, 2 секунды CPU, 1 ГиБ виртуальной памяти, 64 КиБ суммарного вывода; исходный код до 256 КиБ. Файлов условия — до 16, не более 16 МиБ каждый и 32 МиБ суммарно. Поддерживаются однофайловые программы и стандартная библиотека; внешние модули и запись результата в файл не поддерживаются. На Windows текстовые проверки работают, а запуск программ недоступен. При неработающей изоляции загруженный код не исполняется.

## Разработка и сборка

Для разработки нужен Node.js >=22.23.3. Для конечного пользователя готовой сборки он не нужен.

```sh
npm run check
npm test
npm start
npm run build:linux
```

Установка npm-зависимостей не нужна. JSZip 3.10.1, XML-парсер saxes 6.0.0 и xmlchars 2.2.0 включены в `vendor/` вместе с лицензиями; остальные зависимости сервера — встроенные модули Node. UI — HTML/CSS/JavaScript без CDN и внешних шрифтов. `scripts/build.cjs` собирает Linux x86_64 из текущего исполняемого файла Node; рядом с его каталогом `bin` должен находиться `LICENSE`. Для другого расположения задайте `NODE_RUNTIME` и `NODE_LICENSE`. Сборка помещается в `dist/`.

Полная история сохраняется при обычном клонировании репозитория:

```sh
git clone https://github.com/TheLitis/oge-exam-simulator.git
```

В архиве исходников из Releases находится также `repository.bundle`, позволяющий восстановить историю без доступа к GitHub:

```sh
git clone repository.bundle dev-copy
cd dev-copy
```

Скрипт `scripts/publish-github.sh` предназначен для публикации владельцем из клона с историей. Нужны авторизованный GitHub CLI и аккаунт TheLitis. Он создаёт **приватный** `TheLitis/oge-exam-simulator` либо делает обычный push в существующий репозиторий; никогда не использует force push. Исходники, тесты, примеры, лицензии и документация хранятся в Git; готовая Linux-сборка — в Releases. Локальные сеансы, результаты экзаменов, ключи процесса, личные изображения, содержимое виртуальной машины и исходная переписка туда не включаются.

## Ограничения и проверки

Это учебный симулятор, а не сертифицированная экзаменационная станция, защищённый киоск или средство идентификации. Нет блокировки других приложений, удалённого наблюдения, сервера учителя и автоматического выставления баллов. Редактор и проверка работ защищены отдельным паролем. Для работы с недоверенными учениками предпочтительны разные учётные записи ОС: пароль приложения не защищает от изменения его кода, вмешательства в работающий браузер или действий администратора.

См. [docs/QA.md](docs/QA.md) — полный функциональный прогон в MOS и его границы; [docs/MOS-TESTBED.md](docs/MOS-TESTBED.md) — виртуальный стенд МОС 12 и безопасный перезапуск; `docs/MOS-CHECKLIST.md` — проверка на школьном компьютере; `SECURITY.md` — модель угроз и обращение с персональными данными.
